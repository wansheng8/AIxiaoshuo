# 主台升级（双栏持久工作台）— 需求文档

- 特性编号：2026-09-19-studio-workbench
- 状态：待评审
- 关联文档：`2026-09-18-skill-pipeline`、`2026-09-18-studio-flow-redesign`

## 1. 背景

上一轮把写作流水线收敛到 `shared/pipeline.json`，并在主台顶部加了一条纵向阶段卡片流。实际使用后确认：主台的**导航骨架**没有变，仍是 `DESKS`（正文/大纲板/人物/伏笔/设定）+ `TABS`（立项/人物/场景/道具/大纲/细纲/正文）两层，卡片流只是顶部状态带，没有接管流程。用户在选择方案后确定升级为**双栏持久工作台**：

- 左栏固定「阶段轨」，按流水线分组列出所有阶段，常驻可见；
- 右栏「画布」随选中阶段切换，正文阶段保留全宽阅读器；
- 阶段卡片上的运行/编辑/跳过直接驱动画布，去掉水平 `DESKS` 双层跳转。

方案对比（A 阶段单轴 / B 双栏持久 / C 章节时间线）见本次评审记录，选定 **B**。

## 2. 术语

- **阶段轨（Stage Rail）**：工作台左栏，常驻、可收起，按分组列出写作线全部阶段及其状态。
- **画布（Canvas）**：工作台右栏，随选中阶段渲染对应工作面（编辑/阅读/结果）。
- **选中阶段（selectedStage）**：用户当前在阶段轨点选或由任务/章节自动定位的阶段。
- **分组（Group）**：阶段轨上的视觉分段：立项 / 设定 / 大纲 / 正文审校。

## 3. 需求

### 3.1 阶段轨常驻

**R1** 当用户进入主台且桌面宽度足够时，系统应在章节目录与画布之间常驻显示阶段轨，且阶段轨不随画布滚动。

**R2** 阶段轨应按固定分组展示写作线全部阶段：立项（立项）、设定（人物/场景/道具）、大纲（大纲/细纲）、正文审校（正文/续写/润色/审稿/卡壳建议/伏笔账本）。

**R3** 阶段轨每个阶段项应展示阶段名与状态（未开始/进行中/已完成/失败/已跳过），状态与阶段卡片流保持同一数据源。

### 3.2 选中与画布联动

**R4** 当用户点击阶段轨中的阶段时，系统应把该阶段设为选中阶段，并在画布打开对应工作面（编辑/阅读/结果）。

**R5** 当用户通过其他入口改变当前工作面（点章节、点击卡片操作、自动流水线推进）时，系统应把选中阶段同步为对应阶段。

**R6** 当画布显示正文阶段时，应保留全宽阅读/编辑与选区工具条；其他阶段使用既有资产面板，不重复造面板。

**R7** 当存在选中阶段时，系统应在画布顶部展示该阶段的动作卡（状态、产出摘要、依赖、参考、生成/重跑、跳过、查看/编辑）。

### 3.3 去双层导航

**R8** 系统应移除主台中的水平 `DESKS` 标签行，改由阶段轨承担台内导航；小组额外视图（如大纲板、伏笔）应作为阶段轨中的独立入口保留。

**R9** 当用户处于专注（zen）模式时，系统应隐藏阶段轨与目录，只保留画布。

**R10** 当窗口宽度不足以同时容纳目录、阶段轨与画布时，系统应把阶段轨收进可开合抽屉，默认不挤压画布。

### 3.4 兼容与回归

**R11** 系统应保持既有的阶段运行、落盘、跳过持久化、自动开书、拆书台行为不变。

**R12** 系统应保持 `pipeline.json` 为唯一数据源，阶段轨分组只做展示层映射，不新增硬编码阶段清单。

## 4. 非目标

- 不改变 `pipeline.json` 的阶段定义与落盘语义。
- 不重写拆书台（其纵向卡片流保留）。
- 不引入新的运行后端接口。

# 需求文档 · Skill 体系全面升级

## 简介

在墨枢工坊现有 Skill 体系（内置写作 Skill、拆书对标技法覆盖层、自定义 Skill、组合元素、注入机制）之上做四层升级：运行时注入机制、Skill 管理功能与页面、内置写作 Skill 内容质量、重点 Skill 深度打磨。升级保持既有 Skill id 不变，不破坏现有生成契约与本地数据结构。

## 术语表

- **Skill**：一份写作/拆解说明书，含 front matter（id、name、scene、target、order、enabled、inject、elements）与正文。
- **内置 Skill**：`skills/builtin/*.md`，随仓库分发，id 固定。
- **自定义 Skill**：用户创建，存放于 `data/skills/`。
- **覆盖层**：对内置 Skill 的本地覆盖版本，用于写入拆书对标技法。
- **注入**：把一份 Skill 的正文作为额外约束追加到某个流水线阶段的提示词中。
- **组合元素**：可勾选追加到 Skill 之后的可复用约束片段（`elements.json`）。
- **流水线阶段（target）**：`brief/world/characters/props/outline/beats/content/polish/review/threads`。
- **文风激活态**：个人文风（底味）已启用且已有说明书的状态。

## 需求

### 需求 1：Skill 条件注入

**用户故事：** 作为作者，我希望一份对标技法只在特定类型、平台或文风状态下注入，这样同一套 Skill 不会在不适用的稿本里污染提示词。

#### 验收标准

1. 当一份 Skill 声明了注入目标（inject）与注入条件（whenFlow / whenPlatform / whenVoice）时，系统须仅在当前稿本的 craft 满足全部条件时把该 Skill 注入提示词。
2. 当一份 Skill 未声明注入条件时，系统须按现有行为把它注入到全部 inject 目标。
3. 当文风激活态与 whenVoice 声明不一致时，系统须跳过该 Skill 的注入。
4. 若注入目标的父 Skill 被停用，系统须跳过该注入。
5. 系统须在 Skill 管理接口返回每份 Skill 的注入条件与注入目标，供页面编辑。

### 需求 2：Skill 标签与检索

**用户故事：** 作为作者，我希望给 Skill 打标签并按标签或正文检索，这样 Skill 多起来后能快速定位。

#### 验收标准

1. 系统须支持在 Skill 元数据中读写标签列表（tags）。
2. 当作者输入检索词时，系统须在 Skill 名称、适用场景、标签与正文中匹配。
3. 当作者选定一个或多个标签时，系统须只显示命中这些标签的 Skill。
4. 系统须在 Skill 列表项显示标签与来源（内置/覆盖/自定义）。

### 需求 3：Skill 单份文件导入导出

**用户故事：** 作为作者，我希望把单份 Skill 导出为 Markdown 文件、并从 Markdown 文件导入，这样 Skill 能脱离本机在作者之间流转。

#### 验收标准

1. 当作者导出单份 Skill 时，系统须生成含完整 front matter 与正文的 `.md` 文件。
2. 当作者导入 `.md` 文件时，系统须解析 front matter，把其作为自定义 Skill 落库；id 冲突时须生成新 id。
3. 当导入文件缺少必要 front matter 时，系统须用文件名作为名称并补默认 target/order。
4. 系统须保留既有 JSON 批量导出导入能力。

### 需求 4：Skill 编辑历史与差异

**用户故事：** 作为作者，我希望回退前能看到历史版本与当前版本的差异，这样能判断该回退到哪一版。

#### 验收标准

1. 当作者打开历史记录时，系统须列出每个版本的保存时间、字数与摘要。
2. 当作者选中一个历史版本时，系统须展示该版本正文与当前正文的差异（新增/删除行）。
3. 当作者执行回退时，系统须先把当前正文存为一个新历史版本，再覆盖。

### 需求 5：共享质量基线

**用户故事：** 作为作者，我希望全平台共用的最低写作底线集中维护，这样各 Skill 不会出现规则漂移与重复。

#### 验收标准

1. 系统须提供一份共享质量基线（全角标点、系统输出【】、章首承接、去AI 自检、量化验收口径）。
2. 当生成写作类提示词时，系统须注入共享质量基线，且同一约束不得在内置 Skill 正文中重复定义。
3. 当共享质量基线与某 Skill 正文冲突时，系统须以共享质量基线为准并在 Skill 内标注。
4. 当文风激活时，系统须按现有「底味优先」规则收敛平台通用家规，只保留最低阅读格式。

### 需求 6：内置写作 Skill 内容补强

**用户故事：** 作为作者，我希望每个写作 Skill 的输出结构、约束与验收项齐全一致，这样生成结果的稳定性可预期。

#### 验收标准

1. 系统内置的每个写作 Skill 须包含且仅包含一组输出结构小节、约束小节、执行步骤小节。
2. 每个写作 Skill 的验收项须与共享质量基线的量化口径一致（句长、对白、口语词、人类瑕疵、硬禁词）。
3. 当同一指标在多份 Skill 中重复时，系统须以共享质量基线为唯一来源。
4. 每个写作 Skill 须保持 id 不变且 front matter 合法。

### 需求 7：重点 Skill 深度升级

**用户故事：** 作为作者，我希望正文 Skill 与仿写骨架 Skill 达到可直接产出高质量成品的精细度。

#### 验收标准

1. 当使用正文 Skill 时，系统须给出段落节奏、情绪落地、开篇承接、结尾钩子四组可执行约束。
2. 当使用仿写骨架 Skill 时，系统须输出八个维度与一份可直接套用的通用骨架，数字须来自原文。
3. 当仿写骨架被启用时，系统须把骨架注入写作提示词，并声明「只复制统计特征、内容全换」。

### 需求 8：兼容与稳定性

**用户故事：** 作为维护者，我希望升级不破坏现有数据与流程。

#### 验收标准

1. 系统须继续读取旧版 Skill 文件（无 tags、无注入条件时按默认处理）。
2. 系统须保持 `data/skills/`、`data/elements.json` 的既有字段向后兼容。
3. 当新增字段缺省时，系统须按现有默认值运行且不报错。

# 需求文档 · 模型可用性点亮与探测延时

## 简介

作者在设置页接入多家供应商、每家又拉回一长串模型名后，无法直接判断哪些模型当前真的能调通。本需求为每个候选模型增加「可用性探测」：一键或逐个探测后，在模型列表里点亮可用项、显示探测延时，失败项给出原因，让作者一眼分辨能用与不能用的模型，并据此为写作与后续流程挑选模型。探测结果缓存在本地配置中，刷新页面后仍可复原。按流程分别绑定模型不在本轮范围。

## 术语表

- **候选模型**：某供应商下由「拉取列表」返回、或由作者手填的模型名。
- **可用性探测**：服务端向该模型的对话接口发送一条最小请求，等待响应以判断该模型当前是否可调用。
- **探测延时**：从服务端发出探测请求到收到首个内容增量（非流式接口则为收到完整响应）之间的毫秒数。
- **点亮**：探测成功后在该模型名旁显示绿色状态标记。
- **标记三态**：可用（绿）、不可用（红）、未测（灰）；三态均以彩色或空心样式呈现。
- **探测缓存**：服务端持久化的、每个候选模型最近一次探测的状态、延时与时间。
- **过期**：探测缓存中的记录距当前时间超过有效期的状态。
- **当前写章**：`settings.json` 中 `activeId` 指向的供应商，写章与生成默认走这一路。
- **流程（target）**：一次模型调用的用途，如正文生成、审稿、拆书等。

## 需求

### 需求 1：模型可用性点亮与延时展示

**用户故事：** 作为作者，我希望在模型列表里直接看到每个模型是否可用以及探测延时，这样不必逐个试错就知道该挑哪个模型。

#### 验收标准

1. 系统须为每个候选模型显示一个状态标记，标记取值限于可用、不可用、未测三态。
2. 当某模型最近一次探测成功时，系统须以绿色点亮该模型行。
3. 当某模型最近一次探测失败时，系统须以红色标记该模型行，并在行内显示失败原因。
4. 当某模型从未探测、或缓存已过期时，系统须以灰色空心标记该模型行，并显示「未测」。
5. 系统须在模型名旁显示最近一次探测的延时文本，形如「312 ms」。
6. 当缓存过期时，系统须保留并显示上次延时，同时以灰色标记提示需要重测。
7. 系统须使状态标记在三种状态下都保持可见，不依赖纯黑或与背景同色的呈现。
8. 系统须在设置页模型列表与顶栏模型菜单中显示同一份探测状态。

### 需求 2：单模型探测

**用户故事：** 作为作者，我希望只探测某一个模型，这样能在不惊动其他模型的前提下确认它能不能用。

#### 验收标准

1. 当作者点击某模型行的探测按钮时，系统须只对这一个模型发起一次探测。
2. 当探测进行中时，系统须在该模型行显示进行中状态，并阻止该行被重复触发。
3. 当探测返回时，系统须在同一响应中返回成功标志、延时与错误原因。
4. 当探测成功时，系统须更新该模型的标记为可用，并写入本次延时与时间。
5. 当探测在探测超时内没有响应时，系统须把该模型标记为不可用，并在行内显示超时原因。
6. 若探测请求缺少接口地址或必填 Token，系统须直接返回配置缺失提示，且不发起网络请求。

### 需求 3：分组批量探测

**用户故事：** 作为作者，我希望一次测完当前这一组模型，这样新拉回一长串模型名时不用逐个点。

#### 验收标准

1. 当作者点击批量探测按钮时，系统须探测当前分组内的全部候选模型。
2. 当批量探测进行中时，系统须显示已完成数与总数进度。
3. 当某个模型探测失败时，系统须继续探测该组内其余模型。
4. 当批量探测全部结束时，系统须保留每个模型的独立结果，不因部分失败而整体标红。
5. 系统须把批量探测的并发上限限制为 2，并允许作者中止尚未开始的探测。

### 需求 4：探测缓存与时效

**用户故事：** 作为作者，我希望探测结果能记住，这样刷新页面或重启服务后不用重测。

#### 验收标准

1. 当一次探测结束时，系统须把该模型的标记、延时与探测时间写入本地配置。
2. 系统须在读取设置时随模型列表一同返回每个模型的探测缓存。
3. 当缓存记录距当前时间超过有效期时，系统须把该记录标记为过期。
4. 系统须把探测有效期设为 12 小时，并支持通过环境变量覆盖。
5. 当模型名被作者从某供应商的模型列表中移除时，系统须一并清理该模型的探测缓存。
6. 系统须保证探测缓存的写入不改变对话生成的任何既有行为。

### 需求 5：探测的凭据与记录边界

**用户故事：** 作为作者，我希望探测安全且不干扰写作记录，这样密钥不外泄、写章统计不被污染。

#### 验收标准

1. 系统须保证探测错误信息只包含主机名与路径，不包含 API Token。
2. 系统须保证探测请求不写入写作日志、不改变章节字数或状态。
3. 系统须让「探测接口」这一既有入口与本需求的单模型探测共用同一套探测实现。
4. 当探测命中安全拦截或 Token 错误时，系统须把该模型标记为不可用，并在行内显示对应的具体原因。

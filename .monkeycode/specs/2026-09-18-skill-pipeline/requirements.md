# 需求文档 · Skill 流水线统一重设计

## 简介

墨枢工坊当前的 Skill 编排散落在五处硬编码定义里：前端 `Skills.tsx` 的 `TARGETS` 与 `PIPE_IDS`、`Studio.tsx` 的 `STEPS`/`PIPELINE`/`PIPE_SKILL_IDS`/`pipeSkillId`、后端 `skills.js` 的 `TARGETS`/`WRITING_INJECT`/`CRAFT_SLOTS`、`prompt.js` 的 `DROP_ORDER`/`isWritingSkill`、`context.js` 的块顺序与逐 id 特判。这些定义必须手工保持一致，`order` 只影响列表显示、不决定提示词注入顺序，自定义 Skill 插入会撞号，技法指南（guide）统一排在末尾且按名称排序。

本次重设计引入一条**单一数据源的流水线定义**，统一写作线与拆书线的阶段顺序、阶段内排序、提示词装配与注入顺序，并保持既有 Skill id、`data/` 数据结构与生成契约不变。

## 术语表

- **流水线（Pipeline）**：Skill 按固定阶段依次执行、并把各阶段产物注入后续提示词的整体编排。
- **阶段（Stage）**：流水线上的一个位置，含唯一 id、显示名、target、所属分组、顺序、产物栏位与是否写作类。
- **阶段产物（Artifact）**：某阶段生成的资产，包括立项、人物、场景、大纲、细纲、正文、道具、伏笔。
- **排序键（Order）**：同一阶段内 Skill 的相对位置。
- **注入（Inject）**：把某份技法 Skill 的正文追加到指定阶段提示词的行为。
- **写作线**：立项 → 人物 → 场景 → 大纲 → 细纲 → 正文 → 续写 → 润色 → 审稿。
- **拆书线**：拆书章纲 → 拆书角色 → 黄金三章 → 事件线 → 整体/详细/精细大纲 → 提炼技法 → 仿写骨架。
- **技法 Skill**：`target` 为 `guide`、通过 `inject` 挂到阶段上的 Skill。
- **归一化顺序**：系统按流水线定义与稳定平手规则算出的最终顺序。

## 需求

### 需求 1：单一流水线定义

**用户故事：** 作为维护者，我希望阶段顺序只在一处定义，这样新增或调整阶段时不必同步五处硬编码。

#### 验收标准

1. 系统须提供一份共享流水线定义，逐项描述每个阶段的 id、显示名、target、所属分组、顺序、产物栏位与是否写作类。
2. 当系统展示 Skill 列表或执行自动流水线时，系统须从共享流水线定义取得阶段顺序。
3. 后端与前端须从共享流水线定义得到一致的阶段顺序，并可在构建时校验一致性。
4. 系统须由共享流水线定义推导写作类 Skill 集合、可注入目标集合与拆书技法槽位。

### 需求 2：阶段内排序与重排

**用户故事：** 作为作者，我希望把一份 Skill 调到指定位置，且不担心撞号或顺序抖动。

#### 验收标准

1. 当作者把一份 Skill 上移或下移一位时，系统须在单个请求内原子地调整该 Skill 与相邻 Skill 的排序键。
2. 系统须支持在两份已有 Skill 之间插入一份新 Skill，且不改动其它 Skill 的排序键。
3. 当同一阶段内两份 Skill 的排序键相等时，系统须按 id 做稳定平手排序。
4. 当相邻排序键差值小于阈值时，系统须为该阶段重新分配间距，且重排前后的相对顺序保持不变。
5. 系统须拒绝会破坏排序键唯一性的写入，并返回可读错误。

### 需求 3：流水线驱动提示词装配

**用户故事：** 作为作者，我希望各阶段产物按剧情依赖进入提示词，这样模型看到的上下文顺序稳定且正确。

#### 验收标准

1. 当系统生成提示词时，系统须按共享流水线定义决定上下文块的相对顺序；该顺序由流水线定义固定，不开放给作者逐次改写。
2. 系统须按共享流水线定义推导写作类 Skill 集合，不再依赖散落的 id 硬编码。
3. 系统须按共享流水线定义决定技法 Skill 的注入顺序，使注入顺序与阶段顺序一致。
4. 当同一阶段挂有多份技法 Skill 时，系统须按排序键与稳定平手规则决定注入先后。
5. 当阶段被停用时，系统须跳过该阶段的产物块与其挂载的技法注入。

### 需求 4：拆书线纳入同一模型

**用户故事：** 作为作者，我希望拆书 Skill 与写作 Skill 共用同一套排序与展示规则。

#### 验收标准

1. 系统须在共享流水线定义中包含拆书线阶段。
2. 当作者位于拆书台时，系统须只展示拆书线阶段及其挂载的技法 Skill。
3. 当作者位于写作台时，系统须只展示写作线与通用阶段。

### 需求 5：自定义与技法 Skill 归位

**用户故事：** 作为作者，我希望自定义 Skill 和技法说明能出现在对应阶段内，而不是一律堆在末尾。

#### 验收标准

1. 系统须允许自定义 Skill 声明归属阶段，并在该阶段内排序。
2. 当内置 Skill 与自定义 Skill 属于同一阶段时，系统须先排内置、后排自定义，组内各按排序键。
3. 系统须让技法 Skill 随其注入目标阶段排序，而不是统一排到列表末尾。
4. 系统须保持自动开书流水线只执行内置阶段，自定义 Skill 只参与展示与注入排序。

### 需求 6：列表展示

**用户故事：** 作为作者，我希望分组视图与平铺视图的顺序一致，检索不打乱流水线。

#### 验收标准

1. 系统须提供「按流水线分组」与「平铺顺序」两种视图，且两者顺序一致。
2. 当作者检索或按标签筛选时，系统须只过滤结果，不改变流水线顺序。
3. 系统须在列表项标注该 Skill 所属阶段与来源（内置／覆盖／自定义）。

### 需求 7：向后兼容与迁移

**用户故事：** 作为维护者，我希望重设计不破坏既有 Skill 文件与本地数据。

#### 验收标准

1. 系统须继续读取仅含整数 `order`、无阶段字段的旧 Skill。
2. 当旧 `order` 与内置序号冲突或重复时，系统须按稳定规则归一化，且不丢失 Skill。
3. 系统须保留 Skill id 不变。
4. 当文件名数字前缀与共享流水线定义的阶段顺序不一致时，系统须给出提示。

### 需求 8：可验证性

**用户故事：** 作为维护者，我希望归一化顺序可以被接口和测试直接断言。

#### 验收标准

1. 系统须提供接口返回共享流水线定义与每份 Skill 的归一化顺序。
2. 当排序或注入逻辑变化时，系统须能通过该接口与单元测试断言顺序结果。
